About DineMind & Recommendation Methodology

Engineered for Cognifyz Technologies Machine Learning Internship — Task 2 (Restaurant Recommendation System).

Project Mission & Scope

DineMind is a locally runnable, end-to-end restaurant recommendation web application. The core objective is to collect real user dining preferences (such as preferred cuisines, city/locality, budget range, minimum rating, and dining attributes) and compute a personalized, ranked list of matching restaurants.

Unlike primitive restaurant search tools that only perform keyword lookups or item-to-item similarity, DineMind is user-preference first. It computes similarity between the user's preference vector and the multi-dimensional restaurant feature space.

Key Cleaning & Transformation Operations:
  • Schema Mapping: Canonical naming layer maps raw fields (handling Byte Order Mark \ufeffRestaurant ID) into standard internal names.
  • Cuisine Parsing: Multi-label comma-separated strings were tokenized, trimmed, and standardized into 146 canonical cuisine categories.
  • Mojibake Correction: Cleaned character encoding artifacts in international city names (e.g. Bras_lia → Brasilia, So Paulo → Sao Paulo).
  • Numeric Normalization: Sanitized currency formatting, handled unrated listings (2,148 venues with 0.0 rating), and bounded price ranges (1 to 4).

Recommendation Scoring Algorithm

DineMind employs a transparent two-stage candidate retrieval and ranking architecture:

Stage A: Hard Constraints (Pruning)

If strict filtering is toggled by the user, candidate restaurants violating exact boundaries are excluded before scoring:

  • Strict Location: Excludes restaurants outside the selected city or locality.
  • Strict Budget: Prunes venues exceeding the user's maximum price tier or numeric cost.
  • Strict Rating: Excludes venues falling below the user's minimum star rating.
Stage B: Multi-Criteria Content Relevance Scoring

Surviving candidates are scored between 0 and 100 using a normalized weighted combination of active preference components:

Score = 100 * (∑ w_i * s_i) / (∑ w_i)
Preference Component Weight Scoring Formulation
Cuisine Similarity 40% Combination of Cuisine Coverage (0.75) and Jaccard Set Overlap (0.25) across preferred and served cuisines.
Location Match 20% Exact Locality match = 1.0; same City match = 0.6; non-matching = 0.0.
Budget Fit 20% Distance from desired price tier (1 to 4) or proportional closeness to maximum numerical budget.
Rating Quality 15% Normalized aggregate rating (1.0 to 5.0) combined with Bayesian log-vote popularity damping.
Service Features 5% Verification of online delivery and table booking availability if requested.
Weight Renormalization: If a user leaves a preference blank (e.g., leaves budget unspecified), that component is omitted from both the numerator and denominator, preventing unfair penalties on unselected criteria.

Ethical AI & Data Integrity Commitments

  • Zero Data Fabrication: No artificial restaurant names, fake ratings, or hallucinated reviews.
  • No Dietary Guesswork: Because the Cognifyz dataset does not include dietary tags (halal, vegan, allergen-free), DineMind explicitly disables dietary filters rather than guessing from names or cuisine labels.
  • Verifiable Explanations: Every match tag ("Within budget", "Matches cuisine") is directly derived from verified record values.
  • Deterministic Ranking: Tie-breaking is performed deterministically (Score → Rating → Votes → Name), ensuring consistent results.
